### 2.1 Yahoo の chart API

| # | 項目 | 内容 | 確度 |

| F1 | URL | `https://query1.finance.yahoo.com/v8/finance/chart/<symbol>?range=<r>&interval=1d`。`6723.T`、`%5EN225`、`%5EGSPC`。`query2` も 200 | ◎ |
| F2 | HTTP/1.0 の応答 | `HTTP/1.0 200 OK`。**`content-length` あり・`transfer-encoding` なし**(chunked にならない)。ヘッダー名は**小文字**(`date:` `content-length:`)。応答の全体 = 6723.T 1,816 / ^N225 1,834 / ^GSPC 1,862 バイト(`range=1d`、`openssl s_client` で数えた) | ◎ |

| F4 | `meta` のキー(本文の先頭近く) | `currency` `symbol` `regularMarketTime`(UTC 秒)`regularMarketPrice` `chartPreviousClose` `currentTradingPeriod.regular.{start,end}`(UTC 秒)ほか。**`regularMarketPrice` と `chartPreviousClose` は `meta` に 1 回ずつ**。`regular` の中の `start` と `end` の**順序は銘柄で違う**(^N225 は `end` が先) | ◎ |

### 2.2 Yahoo の TLS(`openssl s_client`、OpenSSL 3.5.5。ESP32 側の条件を判断する材料)

| T2 | TLS 1.2 の暗号スイート | **受ける**: `ECDHE-ECDSA-AES128-GCM-SHA256`、`…AES256-GCM-SHA384`、`…AES128-SHA256`、`…AES128-SHA`、`…AES256-SHA`、`…CHACHA20-POLY1305`、`ECDHE-RSA-AES128-GCM-SHA256`、`…AES128-SHA256`、RSA 鍵交換 `AES128-GCM-SHA256`。**拒否**: RSA 鍵交換の `AES128-SHA`(CBC)。つまり**一般的な ESP32(mbedTLS)の ClientHello にある ECDHE-*-AES-GCM / CBC-SHA256 で成立する見込み** | ◎ |

**配色は固定**(切り替えスイッチなし): `dir`(上昇・下落・変化なし)→ 色 = **上昇 → UP(赤)、下落 → DOWN(緑)、変化なし → FLAT(灰)**。帯・ramp は「色の添字(0 = UP、1 = DOWN、2 = FLAT)」で持ち、`dir` と同じ番号にする(写像の関数は無い)。配色を変えたい時は、この §3.2 の表を直して `gen_stock_assets.py` で再生成する。

**色覚への配慮(必須)**: 方向は**色だけで伝えない**。**▲(上昇)/ ▼(下落)の記号と、騰落率の `+` / `−` の符号を必ず併記する**(§4.2)。変化なしは記号なし・符号なし(`0.00%`)。H-7・V-1 で確認する。

## 4. 数値の扱い(float を使わない)

### 4.1 方針

| 項目 | 決定 |
|---|---|
| 内部表現 | 価格 `price_x100`・`prev_x100` は **int32(×100。小数 2 桁)**。前日比 `diff_x100 = price_x100 − prev_x100`。騰落率 `pct_bp` は **int32(0.01% = 1)** |
| 範囲 | `1 ≦ price_x100, prev_x100 ≦ 99,999,999`(= 999,999.99 まで。表示 10 文字に収まる)。外れたら `err = 6`(範囲外) |
| 理由 | RX72N は FPU があるが、`printf` の浮動小数点は ROM を食う(複製元は `snprintf` を整数だけで使う)。**パースも整形も整数だけ**にして、ホスト試験を厳密な文字列一致にする |
| `int64` | `pct_bp` の計算だけ(`diff_x100 * 10000` が最大 1e13 で int32 を超える)。libgcc の `__divdi3` が入る(約 0.5KB。△) |

### 4.2 規則

| 項目 | 規則 |

### 5.2 応答の解析(`wx_parse_http`。標準 C。**応答の本文はログ・ほかへ出さない**。出すのは数値と名前だけ)

全体を 1 つのバッファに溜めてから解析する(**ストリーミングは採らない**: キーは先頭〜1,100 バイトに集まっており、バッファは 3,072 バイトで足りる。ストリーミングは、行をまたぐキー・数値の分割処理が増えるだけで RAM の得が無い)。

| 段 | 内容 | 失敗時 |
|---|---|---|
| 1 状態行 | `HTTP/1.0 ` か `HTTP/1.1 ` + 3 桁。**200 でなければ失敗**(`http` を記録) | `err = 4` |
| 2 `Date:` | ヘッダー部で、**大文字小文字を区別せず**(`date:` が小文字。F2)`Date:` を探し、`<曜日>, <日> <月> <年> <時>:<分>:<秒> GMT` を読む(既存の `find_date` + `wx_parse_date`。◎ ホスト試験済み)。範囲検査あり | `have_date = 0`(株価は成功にできる。時計の同期だけ行わない) |
| 3 本文の始まり | `\r\n\r\n` の後ろ(無ければ全体) | — |
| 4 `meta` の値 | 本文から **`"regularMarketPrice":`**(数値 → `price_x100`)、**`"chartPreviousClose":`**(→ `meta_prev_x100`)、**`"regularMarketTime":`**(uint32 → `mtime`)。**`"regular":{` を見つけ、`}` までの間で `"start":` と `"end":` を別々に探す**(順序が銘柄で違う。F4)→ `rs`、`re`(UTC 秒) | `err = 5`(キーが無い・数値が読めない) |
| 5 直前の足 | `"indicators":` の後ろの **`"close":[`** から `]` まで。要素は数値または `null`(最大 5 要素まで読む)。**2 要素以上で、最後から 2 番目が数値なら `bar_prev_x100`**(`has_bar_prev = 1`) | 無くても成功(`has_bar_prev = 0`) |
| 6 前日の終値の決定 | `prev_x100 = has_bar_prev ? bar_prev_x100 : meta_prev_x100`(**§5.3**) | — |
| 7 範囲 | `price_x100`、`prev_x100` が `1〜99,999,999` | `err = 6` |
| 8 途切れ | 文字列検索は必ず `len` までで止める。**バッファに入りきらなかった場合(`F_OVER`)でも、段 4 のキーが全部そろっていれば成功**(段 5 は無くてもよい)。段 4 が欠ければ `err = 7` | `err = 7` |

**エラー番号(`[stk]` の `err`)**: 1 = TCP/SSL の接続に失敗(`wx_tcp`)/ 2 = 送信失敗(`wx_send`)/ 3 = 応答なし・途切れ(`wx_recv`)/ 4 = HTTP の状態が 200 でない(`http` を見る。**429 を含む**)/ 5 = キー・値が読めない / 6 = 範囲外 / 7 = バッファ超過(キーがそろわない)/ 8 = 接続(`join`)失敗 / **9 = ESP32 が再起動した(受信中に `ready`)**。9 は SSL のメモリ不足の目印(新規)。

### 5.3 前日比の基準(1 案に決める)

| 案 | 内容 | 判断 |
|---|---|---|

### 5.4 市場の状態(取引中 / 終値)の決め方

**入力**: `now_utc`(ソフト時計 = `Date:` + 9 時間 から、JST → UTC は −32,400)、`mtime`(`regularMarketTime`)、`rs` / `re`(`currentTradingPeriod.regular.start / end`)。いずれも UTC 秒。

| 規則 | 内容 |
|---|---|
| `TRADING` | `rs ≤ now_utc < re` **かつ** `mtime ≥ rs` **かつ** `now_utc − mtime ≤ 1,800`(最新の足が 30 分以内) |
| `CLOSED` | 上以外すべて(開場前・閉場後・休日・昼休み中の足の停止・最新の足が 30 分より古い) |
| 時計が未同期 | `mkt = NONE`(丸・文字を描かない) |

**理由**: 日本の銘柄は**約 15 分遅れ**(F8)なので、`now − mtime` が 15 分あっても取引中は正常 → 閾値 30 分。**昼休みも `regular` の区間の中**(F9)なので、`rs ≤ now < re` だけだと 11:30〜12:30 も「取引中」になる。最新の足が 30 分より古くなる 12:00 頃から「終値」(= 前場終値)になり、**昼休みの前半(11:30〜12:00)は「取引中」のまま**になる(△。許容。今回は直さない)。`15:30` を過ぎると**直ちに「終値」**(遅延のため、最終値が確定するのは最大 約 20 分後。次の周期で値が更新される)。
夏時間・祝日: `rs` / `re` は API が UTC 秒で返す(F9)ので機器は意識しない。**祝日の `currentTradingPeriod` の値は未確認**(米国の感謝祭の翌朝は直前の取引日の値だった ◎。祝日で `rs ≤ now < re` が偽になるので `CLOSED`)。

| 見えるもの | 意味 | 次の手 |
|---|---|---|
| `wx_tcp` が **`ERROR` で即時**(`ms` < 500) | SSL を受け付けない(コマンドの状態・メモリ) | `z` を試す。ダメなら (a) へ |

| `http=200` だが `len` が 1,700 未満 | 受信が途中で切れた(`CLOSED` が早い) | `len` と `[wifi] state=... bytes=` を記録して報告 |
| `y` は `http=200`、`z` を使った方だけ失敗/成功 | 検証の既定の違い | `z` が必要なら、本番の取得の前に `AT+CIPSSLCCONF=0,0,0` を 1 step 足す(NVS に保存されるので 1 回でよい) |

**合格の後(T-1 が通った時)**: 同じ手順を **`APP_WIFI_TEST = 1` のまま 10 分おき 3 回**(連続して通るか、ESP32 のメモリが解放されて 2 回目以降も通るか)確認してから、Phase 1 以降の取得に進む(3 銘柄を連続で取るので、**連続して通ること**が本質)。専用モードで `y` を 3 回続けて送る(間隔 15 秒)。

### 5.7 取得の流れ(周期・失敗・429)

**1 周期 = 3 銘柄を順番に、1 銘柄ずつ TCP/SSL を開閉**(`WIFI_RANGE_WX` の 5 step を銘柄ごとに実行。**1 銘柄 = `wx_mux` `wx_close` `wx_tcp` `wx_send` `wx_recv`**)。

| 項目 | 決定 |
|---|---|
| 順序 | 銘柄 0(6723.T)→ 1(^N225)→ 2(^GSPC) |
| 周期 | **周期の開始から 10 分(`WX_INTERVAL_MS` = 600,000)**。起動後は、接続(約 7 秒)の後すぐ 1 周期 |
| 時間の見積 | 1 銘柄 = 接続 + SSL ハンドシェイク(**△ 2〜4 秒**)+ 送受信 0.5 秒 = 約 3〜5 秒 → 1 周期 約 10〜15 秒(**実機で測る**。受入は 1 銘柄 ≦ 30 秒、1 周期 ≦ 90 秒) |
| 更新要求(タッチ・UART `x`) | 待機中なら**直ちに 1 周期**。**前回の周期の開始から `WX_MIN_GAP_MS` = 5,000ms 未満なら無視**(`[stk] req=ignored`)。取得中・接続中は無視(`req=busy`)。オフライン中は直ちに再接続を始める |
| **銘柄ごとの失敗** | 1 銘柄が失敗しても**残りの銘柄は続けて取る**。周期の終わりに、失敗した銘柄だけを **20 秒後(`WX_RETRY_MS`)にやり直す(最大 2 回)**。2 回やり直しても失敗なら、**次の定期の周期まで待つ**(その間、失敗した銘柄は古い値のまま、フッターは F5)。**失敗した銘柄の表示**は §3.9 |
| **429** | 銘柄のどれかで `http=429`: **その周期を打ち切り**(残りは取らない)、**300 秒(`WX_RATE_MS`)後**に周期をやり直す。それまでの値は残す |
| 全部失敗 | 1 周期で 3 銘柄すべてが失敗(`err` 1〜3 または 9)し、やり直しでも全部失敗 → **接続(`WIFI_RANGE_CONNECT`)からやり直す**(ESP32 の再接続)。再接続の間隔は **60 → 120 → 300 秒**(複製元と同じ)。`net` = ERR(オフライン表示) |
| 接続(`join`)の失敗 | 同上(60 / 120 / 300 秒)。`net` = ERR |
| 古い | 最新の成功から 1,800 秒(`WX_STALE_S`)で `stale`。**値は消さない** |
| 接続を保たない | 毎回 TCP/SSL を張って閉じる(`Connection: close`)。**SSL のメモリを毎回解放する**(§2.3 A1 の注記への対処) |

**予定表(`wx_sched_t`)の変更**: 複製元は「1 周期 = 1 回の取得」。**1 周期 = 3 回の取得 + 失敗分のやり直し**に拡張する。

| 追加するもの | 内容 |
|---|---|
| フィールド | `sym`(今の銘柄 0〜2)、`todo`(未取得の銘柄のビット)、`failed`(失敗した銘柄のビット)、`retry_n`(0〜2) |
| `wx_sched_poll` | `WX_ACT_FETCH` を返す時に `wx_sched_sym(s)` で銘柄を伝える。続けて 3 回 |
| `wx_sched_done(s, act, ok, http, now)` | `ok` と `http` を受け、銘柄を進める。429 は打ち切り。最後の銘柄の後に `failed` を見て、`RETRY`(20 秒)か `IDLE` へ |
| 新しい関数 | `uint8_t wx_sched_sym(const wx_sched_t *)`、`uint8_t wx_sched_failed_mask(const wx_sched_t *)`(`partial` の判定用) |

### 7.5 UART ログの追加行(`docs/design-uart.md` の書式に合わせる。**SSID・パスワード・応答本文は出さない**)

**既存のタグ(`[boot]` `[init]` `[hb]` `[err]` `[st]` `[perf]` `[wifi]` `[wifiv]`)は書式を変えない**。`[wx]`(天気)は **`[stk]` に置き換える**(書式が違うので、混同を避けて名前を変える)。`[ev]`・`[ui]`(旧 UI)は**削除**し、`[ev] btn=tap src=<touch|uart>` を 1 種類だけ出す。

```
[stk] res=ok sym=<0|1|2> src=<boot|timer|touch|uart|retry> p100=<n> c100=<n> bp=<n> mkt=<t|c|n> http=<n> ms=<n> sync=<0|1> jst=<hhmmss|none> len=<n> closed=<0|1>
[stk] res=fail sym=<0|1|2> src=<…> err=<1..9> http=<n> ms=<n> len=<n>
[stk] cycle=<n> ok=<mask 0..7> fail=<mask 0..7> ms=<n>
[stk] req=<ignored|busy|off> src=<touch|uart>
[stk] net=<off|conn|on|err> busy=<0|1> have=<mask 0..7> stale=<mask 0..7> clk=<hhmmss|none> upd=<hhmm|none>
[stk] sym=<0|1|2> have=<0|1> p100=<n> d100=<n> bp=<n> dir=<u|d|f> mkt=<t|c|n> age=<-1|n>
[ev] btn=tap src=<touch|uart>
```

| キー | 意味 |
|---|---|
| `p100` / `c100` / `d100` | 現在値 / 前日の終値 / 前日比(×100 の整数。`c100 = prev_x100`、`d100 = diff_x100`。符号つき) |
| `bp` | 騰落率(0.01% = 1。符号つき。`231` = +2.31%) |
| `mkt` | `t` = 取引中 / `c` = 終値 / `n` = 不明(時計が未同期) |
| `src` | `boot` = 起動後の最初の周期 / `timer` = 10 分ごと / `touch` / `uart` = 更新要求 / `retry` = 失敗分のやり直し |
| `len` | 受信したバイト数(本文は出さない) |
| `ok` / `fail` / `have` / `stale` | 銘柄のビット(bit0 = 6723.T、bit1 = ^N225、bit2 = ^GSPC) |
| `dir` | `u` = 上昇、`d` = 下落、`f` = 変化なし(意味の方向。色は `u` = 赤、`d` = 緑、`f` = 灰で固定) |
| `age` | その銘柄の最後の成功からの秒(未取得 `-1`) |

- **`[stk] res=ok` / `res=fail` は取得 1 回に 1 行**(銘柄ごと。1 周期で 3〜5 行)。`cycle=` は周期の終わりに 1 行。`net=` は変わった時と `s` の時。`sym=` の 3 行は `s` の時だけ。
- **行キュー(8 行)の溢れ(`drop`)を避ける**: 製品では `[wifi] step=... res=start` と `[wifiv] key=oth` を出さない(複製元と同じ。`wifi_core_set_quiet`)。**1 周期で最大 `[stk]` 5 行 + `[wifi]` 15 行(5 step x 3 銘柄)**になるので、**`[wifi]` の `res=ok` 行は製品では出さず、失敗・時間切れだけ出す**(§5.9 の `wifi_core` の変更に含める)。**判定: `drop = 0`**。
- 書式の正規表現(Python の `re`、1 行ずつ `fullmatch`):

```
R-STK-OK    : \[stk\] res=ok sym=([0-2]) src=(boot|timer|touch|uart|retry) p100=(\d{1,8}) c100=(\d{1,8}) bp=(-?\d{1,7}) mkt=([tcn]) http=(\d{3}) ms=(\d+) sync=([01]) jst=(\d{6}|none) len=(\d+) closed=([01])
R-STK-FAIL  : \[stk\] res=fail sym=([0-2]) src=(boot|timer|touch|uart|retry) err=([1-9]) http=(\d{1,3}) ms=(\d+) len=(\d+)
R-STK-CYCLE : \[stk\] cycle=(\d+) ok=([0-7]) fail=([0-7]) ms=(\d+)
R-STK-REQ   : \[stk\] req=(ignored|busy|off) src=(touch|uart)
R-STK-NET   : \[stk\] net=(off|conn|on|err) busy=([01]) have=([0-7]) stale=([0-7]) clk=(\d{6}|none) upd=(\d{4}|none)
R-STK-SYM   : \[stk\] sym=([0-2]) have=([01]) p100=(\d{1,8}) d100=(-?\d{1,8}) bp=(-?\d{1,7}) dir=([udf]) mkt=([tcn]) age=(-1|\d+)
R-EV-TAP    : \[ev\] btn=tap src=(touch|uart)
```

- 秘密・本文の混入の検査(H-S): 応答に目印の語(`BODY_SENTINEL`)を入れて流し、**全ログ行に出ない**。ログの語として `"chart"` `regularMarketPrice` `HTTP/1` `query1` `Date:` `GET /` `+IPD` が**1 件もない**こと。

## 11. ユーザーに確認したい点(最大 3)

1. **TLS が通らなかった時に、ESP32 の AT を 2.x へ書き換えてよいか(推奨 (a))**。書き換え前に 4MB 全体を退避する。ESP-AT と esptool のダウンロードは、そのつど許可を取る。許可が出ない場合は (b) PC 側の中継(ガジェットが単体で動かなくなる)になる。**Phase 0 の結果が出てから聞く**ので、今は「方針としてよいか」だけ。
2. **前日比の基準を `range=2d`(直前の足の終値)にしてよいか**。依頼文の `range=1d` は、寄り付き直後に **6723.T の前日の終値を 2 営業日前の値で返した**(実測。+2.31% と表示されるところが、本当は 0%)。`range=2d` なら前日の終値が取れる。URL が依頼文と変わる。戻す時は定数 1 か所。
3. **日本の銘柄・日経平均は約 15 分遅れの値(Yahoo の仕様。実測)。画面に「15分遅れ」と出すか**。出すなら、フッター左の「10分ごとに自動更新」を「10分ごとに自動更新(15分遅れ)」に変える(帯 1 枚の文言だけ)。出さないなら今のまま。

(フッターを 22px にしたこと、日経平均のコードを `N225` と書くことは、設計側で決めた。違っていれば V-0 のプレビューで直す。)
