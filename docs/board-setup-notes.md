| 項目 | 値 | 出典 |
|---|---|---|
| BSPのSCIターミナル | **無効**(`BSP_CFG_SCI_UART_TERMINAL_ENABLE = 0`)。チャネルは9が既定値、ビットレート115200 | `r_bsp_config.h` / `.scfg` |

## 4. デバッガが接続できないとき(ユーザーに伝える順)

| 順 | 確認 | 備考 |
|---|---|---|
| 1 | USBケーブルとE2 Liteの接続(LED状態)、他のデバッガ/ターミナルソフトが掴んでいないか | |
| 2 | **DIPスイッチの位置**をユーザーに見てもらい、ユーザーズマニュアルの設定表と照合する | `.scfg` のピン名に `ET0RST(SW1-1ch)` があり、SW1には機能ごとのチャネルがある |
| 3 | デバッグ構成の接続方式(JTAG/FINE)が基板と合っているか | 下記の不一致の可能性を参照 |
| 4 | 電源(外部電源ジャックの有無)、リセット状態 | |

**接続方式の不一致の可能性(要確認)**

| 場所 | 値 |
|---|---|
| `.scfg` の System タブ | デバッグインタフェース = `fine` |
| `rx72n_gcc HardwareDebug.launch` | サーバ引数 `-uUseFine= 1`、属性 `jtag.or.fine = 1`、`fine.baud.rate = 1.50`、`mode_pin = 0` |

`-uUseFine= 1` と `jtag.or.fine = 1` が食い違って見える。e² studio でデバッグ構成を開いて保存すると引数が更新される可能性があるが、**未確認**。接続できない場合は、e² studio のデバッグ構成 → デバッガタブで接続方式を確認する。

## 7. COMポート確認(2026-11-19 22:16 ユーザー申告)

- CN8接続時、デバイスマネージャーに「USB シリアル デバイス (COM7)」が出現(Windows標準のCDC ACMドライバ名)。
- **どのデバイスか未特定**。候補: (a) ボード上のUSB-シリアル変換IC → SCIに接続(ログ出力に使える)、(b) RX72N自身のUSB機能(CDC)。(b)ならRX72Nにファームを書いたときだけ出るため、ログには別途USBドライバが要る。
- 特定方法: COM7のプロパティ → 詳細 → ハードウェアID の `VID_xxxx&PID_xxxx`。または CN8 を抜いて COM7 が消えるか確認。
- 未確認: CN8が繋がるSCIチャネルとピン。
