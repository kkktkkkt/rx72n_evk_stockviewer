## 4. 切り分けの考察

- 失敗しなかったので、§5.5.5 の切り分けは使っていない。`z` は実行していない(ESP32 のフラッシュに設定を残していない)。
- AT 1.1.3.0 の `AT+CIPSTART="SSL"`(証明書の検証なしの既定)で、Yahoo の TLS(ハンドシェイク込みで接続 約 2.8 秒)が通る。設計の見込み(2〜4 秒)の範囲内。
- 製品の 1 周期(3 銘柄)は、`wx_tcp` 約 2.8 秒 + 送受信 約 0.3 秒 = 1 銘柄 約 3.1 秒 → 約 9.5 秒(+ 開閉)。受入基準(1 銘柄 ≦ 30 秒、1 周期 ≦ 90 秒)に対して余裕がある。
- 受信バッファ `WX_BUF_SIZE`=3,072 は Yahoo(1,832〜1,838)に十分。`g` では上限で `err=7` が想定どおり出る。
- 注意点(コーディング担当へ。不具合ではない): ① `drop=1` はログの行キュー(8 行)が接続中に溢れた 1 回。製品モードは `res=ok` を出さない設計(§5.9)なので解消する見込み。② `g` のように大きな応答では、バッファが満杯のあとも受信を続けて 8 秒かかる(`err=7` の判定は即時にできるが、`CLOSED` を待っている)。Yahoo では起きないので対応は不要。

## F6. 所見(コーディング・設計への返し。製品コードは修正していない)

4. `[wifiv] key=ip` が UART に出る(IP アドレス。設計 §7.5 は「SSID・パスワード・応答本文は出さない」で IP は対象外)。生のログ `jobs/dbg/p5-serial-*.out` には IP が含まれるので `docs/` にコピーしない。
