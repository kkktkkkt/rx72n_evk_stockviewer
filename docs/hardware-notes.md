## 3. タッチパネル(I2C)関連ピン

| ピン番号 | ボード信号名 | ポート | 信頼度 | 根拠 |
|---|---|---|---|---|
| 25 | LCD-TOUCH-INT | P34(IRQ4) | ○ | hirakuni45/RX の IRQ表で 144ピンの P34 = 25番ピン、IRQ4 |
| 26 | LCD-TOUCH-SCL | P33 = SSCL6 | ○(2026-11-19 更新) | LVGL公式ポート(lvgl/lv_port_renesas_rx72n-envision-kit)の `.scfg`: SSCL6 = ピン26。Renesas公式Wikiもタッチは SCI6 のI2C。FIT `r_sci_iic_rx` のソースで SSCL6 = RXD6側ピン(PB0)、SSDA6 = TXD6側ピン(PB1) → P33(RXD6) = SSCL6 |

| 設定方式 | `GLCDC_CFG_CONFIGURATION_MODE` が `0`: `glcdc_cfg_t` をユーザーコードで埋める(既定)。`1`: `r_glcdc_rx_config.h` の `LCD_CH0_*` マクロで設定 |

| 既定の出力 | RGB565、リトルエンディアン、RGB順、同期エッジ立ち上がり |
| 既定のTCON | HSYNC = TCON2、VSYNC = TCON0、DE = TCON3(上表のボード配線と一致) |
| 既定の極性 | HSYNC/VSYNC: Low active、DE: High active |
| 既定のレイヤ | GR2: ベース `0x00800000`、480x272、ラインオフセット960バイト、RGB565 / GR1: ベース `NULL` |
| フレームバッファ | 480 x 272 x 2 = **261,120バイト**。RAM2(`0x00800000`、512KB)に収まる |

### 8.1 入力形式と CLUT8

| 項目 | 値 | 信頼度 | 出典 |

| 対応する入力形式 | RGB565(0)、RGB888 32bit(1)、ARGB1555(2)、ARGB4444(3)、ARGB8888(4)、**CLUT8(5)**、CLUT4(6)、CLUT1(7) | ◎ | `r_glcdc_rx_if.h` の `glcdc_in_format_t`、AN p.24 |

### 8.8 2026-11-21 追加調査(設計担当): GLCDC の CLUT8 表示(ハードウェアマニュアルの確認)

**調べた理由**: ユーザーの質問「CLUT8 のデータは GLCDC が自動で色に変換して表示するのか」に、ハードウェアマニュアルで答える。§8.1〜§8.7 は FIT のソースとアプリケーションノートだけが根拠だった。

#### 結論(先に)

| # | 結論 | 信頼度 |
|---|---|---|
| 1 | **GLCDC が自動で変換する**。画素ごとにハードがパレット(CLUT)を引き、32bit の ARGB8888 に直して後段へ渡す。ソフトでの展開は要らない | ◎ |
| 2 | 「RGB565 に戻る」のではない。**どの入力形式も内部では RGB888(+A)になり、パネルへ出す直前に1回だけ**、出力形式(この基板は RGB565、切り捨て)へ丸められる | ◎ |
| 3 | GR1 と GR2 は**どちらも CLUT8 / CLUT4 / CLUT1 / RGB565 / RGB888 / ARGB1555 / ARGB4444 / ARGB8888 に対応**し、層ごとに形式を選べる。CLUT も層ごとに別(2セット × 256 エントリー) | ◎ |
| 4 | パレットの書換えは **いつでも可能だが、使用中のセットへ書くと即時に画面へ出る**(垂直同期を待たない)。**垂直同期に揃えるには「使っていないセットへ書く → SEL を切り替える → VEN」**。この SEL はフレームバッファのアドレス(GRnFLM2)と**同じ VEN で同時に反映**される | ◎ |
| 5 | CLUT8 の 480画素の行は **512バイト幅**にする必要がある(64バイト単位で読むため)。マクロライン(複数行を1塊にする設定)でも詰められない | ◎ |
| 6 | 層ごとに別のパレット・別の位置と幅が持てる。**「画面の外へ出せない」はマニュアルの本文では確認できなかった**(図が読めない)。FIT のコードが禁止している | FIT ◎ / マニュアル ？ |

#### 質問1: 自動変換の有無と、変換後の色

| 項目 | 答え | 信頼度 | 出典 |
|---|---|---|---|
| CLUT8 を自動で色にするか | **する**。グラフィックデータインタフェース部(層ごとに1つ)が、読んだ画素の値をそのまま CLUT のアドレス(00h〜FFh)にして色を引く。引いたデータ(ARGB8888)を非同期転送部(4画素のリングバッファ)へ送る。ソフトが画素ごとに展開する処理は無い | ◎ | HW §51.1.4、§51.1.8(3)、§51.2.14 の FORMAT の説明 |
| 変換後の色の形 | **ARGB8888(32bit。A 8 / R 8 / G 8 / B 8)**。直接色(RGB565 など)も同じ ARGB8888 に「拡張」されてから混合へ進む。CLUT の中身も ARGB8888 の形 | ◎ | HW 表51.1(CLUTメモリ)、§51.1.1、§51.1.4 |
| その後の経路 | 混合(下の層とのアルファブレンド)→ パネル用補正(輝度・コントラスト・ガンマ。内部は各 10bit)→ ディザ/丸め → 出力形式への変換 → LCD_DATA 端子 | ◎ | HW §51.1.1、§51.1.6 |
| パネルへ出る色深度 | 出力形式は OUTSET.FORMAT で選ぶ: RGB888 24bit / RGB666 18bit / **RGB565 16bit** / シリアル RGB888。丸めは PANELDTHA.SEL: 切り捨て / 0捨1入 / 2×2 ディザ。**このプロジェクトは RGB565、ディザ無し(切り捨て)、補正無し**(`lcd_panel.c` の `lcd_build_cfg`) | ◎ | HW 表51.1、§51.2.43、§51.2.47、`src/app/lcd_panel.c` |
| RGB565 に「戻る」のか | **戻るのではない**。入力が RGB565 でも CLUT8 でも、混合の間は 8bit × 3 の色で、パネルの 16 本の線へ出す所で上位 5/6/5 bit だけが使われる。**パレットは 24bit の色で指定できるが、見える色はそのうち上位 5/6/5 bit** | ◎(経路)/ ○(「上位 5/6/5 が見える」は切り捨て設定からの導出) | 同上 |
| RGB565 画像と同じ見た目にする作り方 | パレットの値 = RGB565 の各色を 8bit へ広げた値(R = R5 << 3 など、下位ビットは何でも可。切り捨てで同じ 565 に戻る)、A = FF | ○(導出。実機未確認) | |
| A(アルファ)の扱い | CLUT の A は**ピクセル単位アルファブレンドの時だけ**使われる(`DISPSEL = 11b`、`ARCON = 0`)。「カレント画面(`DISPSEL = 10b`)」では A は無視され RGB 部だけが出る。FIT の `blend_control = NONE` かつ `visible = true` は 10b。現行の P1(GR2 のみ)と同じ | ◎ | HW §51.2.15 の表51.9、[FIT] `r_glcdc_blend_condition_set` |

- 形式は層ごとのレジスタ(`GRnFLM6.FORMAT[2:0]`)なので、**GR1 を CLUT8、GR2 を RGB565 にする、のような組合せもハードの上では可能** ◎。

- **GRnFLMRD.RENB(フレームバッファ読出し許可)は、GLCDC の動作中(`BGMON.EN = 1`)は書き換えない**とされている ◎(HW §51.2.10)。FIT は `R_GLCDC_Open` の時に `input[frame].p_base != NULL` の層だけ読出しを許可し、許可されていない層への `LayerChange` / `BufferChange` / `ClutUpdate` はエラーを返す ◎([FIT] `r_glcdc_rx.c` L140〜153、L492 ほか)。**→ 2層を使うなら、現行の `lcd_panel.c` が GR1 を `p_base = NULL` にしている点を変え、Open の時点で両方の層に面を渡す必要がある**。
